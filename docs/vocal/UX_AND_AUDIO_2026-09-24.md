# 声乐跟练入口与移动媒体音频修订

日期：2026-09-24。此文件记录网页实现，不记录个人能力通过。

## 本次问题

短练习数量已经足够，但让用户先选几十张卡、理解音名、配置上下限再开始，仍然不符合跟练目的。用户允许段间点手机，优先要求看得懂、能跟上、准备和单条时长合适。同时报告移动设备上的声音小，似乎不受通常的媒体音量控制。

## 默认入口

- 声乐首页和日常页直接提供“开始今天的跟练”与“先试声音”。
- 七类专项页面共用同一跟练组件；每页有预先编排的默认队列，不强迫自行选卡。
- 38 个原练习 ID 保留在可展开的完整练习库；设置与技术说明默认折叠。
- 默认日常队列：轻哼、mum 轻起音、固定同调三遍、小声/正常/小声、不规则旋律延迟回唱。使用默认设置时音轨合计约5分34秒，自行休息另计。这不是固定训练剂量，也不代表必须唱完。
- 默认范围用于先学会操作与协调，不是对个人换声点或高音能力的测定；固定基线与真实学习关卡不因 UI 变动而改变。
- 每项先准备至少8秒，再完整听参考音、数拍、跟唱；下一项只有手动确认后才开始，并重新给准备时间。
- 暂停后恢复会回到当前乐句的准备段；画面只显示当前动作、逐音歌词/音节和剩余时间。

## 音频架构

原跟练器直接把 Web Audio 振荡器输出到 AudioContext.destination。新跟练器把每条练习生成 PCM WAV，使用真正的 HTML audio 元素播放，不用循环静音文件伪装媒体播放。

在支持的浏览器上额外请求 navigator.audioSession.type = 'playback'；不支持时仍通过媒体元素输出。没有麦克风权限申请，没有录音，也不选择 play-and-record。声音测试与正式练习走同一通道。页面不控制系统音量，只提供有上限的音轨响度选项。

音轨包含起音、示范、倒数、练习与休息；画面读取 audio.currentTime，不再依赖相互独立的逐音计时器。合成音包含谐波、连续长音和滑音，按实际峰值与活动段均方根电平归一化并留余量。停止/卸载会暂停媒体、移除资源并释放 Blob URL。

技术依据：

- WebKit 237322：https://bugs.webkit.org/show_bug.cgi?id=237322 。问题描述区分 Web Audio 和媒体元素在 iOS 静音开关下的行为；2024-09-25 的 WebKit 工程师回复说明 iOS 17 起可显式请求 playback，而默认 ambient 受静音影响。
- W3C Audio Session 工作草案：https://www.w3.org/TR/audio-session/ 。区分 ambient、playback、play-and-record，并定义媒体元素/AudioContext 的集成行为。此 API 不能假定所有浏览器支持。

这两项支持移动音频路由的修复方向，但未取得用户手机型号、系统、浏览器及实际输出路由，不能据此断言该设备的唯一原因。

## 内容参考边界

本次核对了南门声乐基础练声 BV1QG4y1G7Fk、男声练声 BV1LRqHB1EWf、头声练习 BV1ueswzNEvc 的公开介绍与目录。核对范围不包括完整视频音轨、逐帧画面、各段精确时间或真人发声动作。

因此只借鉴预先排好训练顺序、让用户直接进入跟练的形式。不复制其视频、MIDI、录音或课件，也不把本站合成音冒充其范唱。本站仍缺真人范唱；文字、音高/节奏示意不能替代真人动作示范和教师反馈。

## 回归范围

### 已执行

- 本地 Node 测试7项通过：38 ID/7队列、时间轴与音域边界、同调三遍、分阶段元音、高点连续长音、真正静默的记忆间隔、英语弱起/延音、PCM WAV 电平/文件头以及可选播放会话 API。
- 本地系统 Chromium，以390×844视口加载由组件和同一模块生成的内存测试页面：默认折叠、声音测试、实际媒体时间推进、逐音高亮、暂停后倒数、手动下一项、停止释放资源、无横向溢出和无页面脚本错误均通过。
- 本地测试模块与提交至分支的模块使用 Git blob SHA 核对一致。

### 尚未由本地测试证明

- 没有真实 iPhone、Android、蓝牙耳机或用户的应用内浏览器测试；WebKit 测试浏览器在当前环境未安装。
- 本地 Chromium 测试使用内存页面，不等于完整 Astro/Starlight 构建或线上站点检查。完整 npm test、Astro 构建与链接检查由仓库 Actions 执行，结果以对应提交的 workflow 为准。
- 不宣称所有移动设备的响度/静音行为都已解决，或已达到真人跟练视频的示范质量。
